## 3. Test Strategy

### 3.1 Test Levels and Tools

*Sumber: PRD v4.6 §19.1*

| Lapisan | Tool | Owner |
|---|---|---|
| Unit BE | Go `testing`, race detector | BE-1, BE-2 |
| Integration per service | Go test + Compose (PostgreSQL, Valkey, RabbitMQ, Mailpit nyata) | BE-1, BE-2 |
| Contract (internal API + event) | OpenAPI/JSON Schema validation + consumer test | BE-1, BE-2 |
| Acceptance (BDD) | Cucumber/godog | BE + WEB-2 |
| API functional & mock | Apidog | BE-1 |
| Web E2E | Katalon | WEB-2 |
| Mobile E2E | Appium | MOB-1 |
| Unit FE | Jest/Vitest + RTL | WEB-1, WEB-2, MOB-1 |
| Performance | k6 | BE-1 |
| Security | gosec, govulncheck, SonarCloud, Trivy, ZAP | BE-1 |
| Test management | Zephyr Scale | Semua |


**Penerapan di repository (v1.2).** Unit test memakai testify dan mock `_mock/` (`go tool mockgen`); setiap fungsi punya test regresi table-driven (D-27). Integration test adapter (PostgreSQL, Valkey, RabbitMQ nyata) memakai build tag `integration` dan **sudah berjalan di CI** stage `case-coverage` dengan service container; lokal: `make infra && make test-integration`. Contract test respons terhadap `docs/contracts/openapi/*.yaml` memakai validator OpenAPI 3.1. BDD (godog) dan E2E lintas service ditambahkan saat alur Queue → Booking → Payment pertama siap.

### 3.3 Test Design Techniques (ISO/IEC/IEEE 29119-4)

Equivalence partitioning dan boundary value (NIK, kuota, TTL, batas ubah); state transition (antrean, admission, booking, payment attempt — SDD §4.8); decision table (zona peluang, hasil resolve); scenario testing (journey web/mobile); random/property-based (harness jaminan, simulasi acak); experience-based (exploratory pada navigasi back dan koneksi putus).

### 3.4 Entry, Exit and Completion Criteria

#### Release Gates

*Sumber: PRD v4.6 §19.3*

- Semua MUST implemented, reviewed, verified.
- Tidak ada oversell, pelanggaran jaminan admission, NIK pemegang ganda, atau pelanggaran FIFO.
- Tidak ada ubah pesanan yang merusak pesanan lama, ubah setelah pesanan terkunci, atau hold ganda akibat retry.
- Matriks callback Midtrans Sandbox aktual lulus (sukses, pending, expired, duplikat, out-of-order, signature salah, timeout, terlambat).
- Payment page lulus di web dan WebView Android.
- Bypass origin ditolak; local clean-room, ASG, backup/restore, outbox/DLQ lulus.
- Tidak ada temuan critical/high tanpa risk acceptance.

#### Release Blockers

*Sumber: PRD v4.6 Lampiran I.2*

- Oversell, over-allocation, atau customer admitted gagal hold padahal masih dalam TTL dan memilih ≤ N tiket dari kategori tersedia.
- Customer admitted ditolak karena kuota NIK pembeli, atau aturan pembelian baru muncul setelah masuk halaman beli.
- Ubah pesanan yang gagal mengubah pesanan lama; pesanan berubah setelah "Bayar"; nominal di gateway berbeda dari versi terkunci.
- Refresh, koneksi putus, atau tombol back menghilangkan reservasi atau membuat hold/transaksi ganda.
- Perubahan konfigurasi memendekkan sesi yang sedang berjalan atau mengubah aturan jaminan setelah penjualan dibuka.
- NIK pemegang ganda per event atau kuota pembeli > 3.
- Queue bypass, token replay, atau pelanggaran FIFO.
- Booking PAID tepat waktu tetapi dibatalkan, atau stok dilepas tanpa resolve.
- Callback duplikat menggandakan tiket.
- Outbox event hilang; consumer ack sebelum efek durable.
- Payment page token dapat dipakai ulang; ALB dapat diakses langsung.
- Secret/PII di log, metrik, screenshot, fixture, atau repository public.
- Coverage BE < 80% tanpa waiver tertulis.
- Local clean-room gagal menjalankan full flow.
- Klaim Midtrans Sandbox, WebView, ASG, kapasitas, atau CI tanpa evidence aktual.

#### Mermaid Validation Gate

*Sumber: PRD v4.6 §19.4*

Semua blok Mermaid dirender Mermaid CLI di CI; build dokumentasi gagal bila ada yang tidak dapat dirender.

### 3.5 Suspension and Resumption Criteria

Suspend bila smoke test gagal, environment staging tidak tersedia > 4 jam, atau Midtrans Sandbox tidak dapat dihubungi saat matriks pembayaran; resume setelah perbaikan diverifikasi dengan smoke test.

### 3.6 Test Data

Data sintetis dari seed (`docker compose run --rm seed`); NIK sintetis yang valid secara struktur (SDD §4.9, M.5); tidak ada NIK nyata di fixture, screenshot, atau log.

### 3.7 Test Environment

Lihat HLD §4.5 (environment matrix): local-assessor, development, CI, staging/demo.

### 3.8 Retesting and Regression

Setiap PR menjalankan pipeline bertahap (Engineering Handbook §2): quality dan security scan, unit test dengan race detector dan ambang coverage, build, serta scan image. Integration, BDD (godog), dan contract test dijalankan lokal terhadap Docker Compose dan masuk pipeline saat fitur pertama siap. Regression E2E web/mobile dijalankan sebelum rilis kandidat.

```sql
-- Reference harness v4.4: implementasi acuan langkah Lampiran C (reservasi, klaim, cek NIK pemegang,
-- hold, ubah pesanan sebelum bayar, kunci saat "Bayar", akhir TTL detail, bayar/expire) untuk menguji
-- jaminan "masuk = pasti bisa beli". Bukan kode produksi; kode Go wajib lulus skenario yang sama.
\set ON_ERROR_STOP 1

-- Reservasi saat admission (C.2). Konfigurasi event di-snapshot ke admission.
CREATE OR REPLACE FUNCTION booking_t.reserve(p_event uuid, p_seq bigint, p_visitor uuid, p_buyer bytea)
RETURNS TABLE(outcome text, admission_id uuid, units int) LANGUAGE plpgsql AS $$
DECLARE
  s booking.event_supply%ROWTYPE;
  q booking.buyer_quotas%ROWTYPE;
  ev booking.events%ROWTYPE;
  v_free int; v_units int; v_id uuid;
BEGIN
  SELECT * INTO ev FROM booking.events WHERE id = p_event;
  IF EXISTS (SELECT 1 FROM booking.admissions a WHERE a.event_id = p_event
             AND a.status IN ('RESERVED','ACTIVE','EDITABLE')
             AND (a.buyer_nik_hash = p_buyer OR a.visitor_id = p_visitor)) THEN
    RETURN QUERY SELECT 'ALREADY_ACTIVE', NULL::uuid, 0; RETURN;
  END IF;
  SELECT * INTO s FROM booking.event_supply WHERE event_id = p_event FOR UPDATE;
  INSERT INTO booking.buyer_quotas(event_id, buyer_nik_hash, max_quantity)
  VALUES (p_event, p_buyer, ev.max_tickets_per_buyer_nik) ON CONFLICT DO NOTHING;
  SELECT * INTO q FROM booking.buyer_quotas WHERE event_id = p_event AND buyer_nik_hash = p_buyer FOR UPDATE;
  IF q.max_quantity - q.held_quantity - q.paid_quantity <= 0 THEN
    RETURN QUERY SELECT 'BUYER_QUOTA_EXHAUSTED', NULL::uuid, 0; RETURN;
  END IF;
  v_free := s.total_capacity - s.allocated_units - s.held_units - s.sold_units;
  IF v_free <= 0 THEN
    IF s.allocated_units + s.held_units > 0 THEN
      RETURN QUERY SELECT 'NO_SUPPLY_NOW', NULL::uuid, 0;
    ELSE
      RETURN QUERY SELECT 'SOLD_OUT', NULL::uuid, 0;
    END IF;
    RETURN;
  END IF;
  v_units := least(ev.max_tickets_per_order, q.max_quantity - q.held_quantity - q.paid_quantity, v_free);
  INSERT INTO booking.admissions(event_id, queue_entry_id, queue_seq, visitor_id, buyer_nik_hash, buyer_email,
                                 units, status, expires_at,
                                 cfg_selection_ttl_seconds, cfg_payment_ttl_seconds, cfg_submit_grace_seconds,
                                 cfg_edit_enabled, cfg_max_edits, cfg_allow_mixed_categories)
  VALUES (p_event, gen_random_uuid(), p_seq, p_visitor, p_buyer, 'b@example.test', v_units, 'RESERVED',
          now() + make_interval(secs => ev.claim_window_seconds),
          ev.selection_ttl_seconds, ev.payment_ttl_seconds, ev.selection_submit_grace_seconds,
          ev.selection_edit_enabled, ev.max_selection_edits, ev.allow_mixed_categories)
  RETURNING id INTO v_id;
  UPDATE booking.event_supply SET allocated_units = allocated_units + v_units, version = version + 1
   WHERE event_id = p_event;
  RETURN QUERY SELECT 'GRANTED', v_id, v_units;
END $$;

-- Klaim: TTL detail diambil dari snapshot, bukan dari konfigurasi event saat ini.
CREATE OR REPLACE FUNCTION booking_t.claim(p_adm uuid) RETURNS text LANGUAGE plpgsql AS $$
DECLARE a booking.admissions%ROWTYPE;
BEGIN
  SELECT * INTO a FROM booking.admissions WHERE id = p_adm FOR UPDATE;
  IF a.status = 'ACTIVE' THEN RETURN 'ACTIVE'; END IF;                -- idempoten (retry klien)
  IF a.status <> 'RESERVED' OR a.expires_at <= clock_timestamp() THEN RETURN 'TURN_MISSED'; END IF;
  UPDATE booking.admissions SET status = 'ACTIVE', claimed_at = now(), admission_jti = gen_random_uuid(),
         expires_at = now() + make_interval(secs => a.cfg_selection_ttl_seconds)
   WHERE id = p_adm;
  RETURN 'ACTIVE';
END $$;

-- Cek NIK pemegang saat diketik (sesi ACTIVE atau EDITABLE). NIK yang sama dicek ulang tidak dihitung.
-- NIK yang sedang dipegang pesanan milik sesi ini sendiri dianggap AVAILABLE (mode ubah).
CREATE OR REPLACE FUNCTION booking_t.check_attendee(p_adm uuid, p_nik bytea) RETURNS text LANGUAGE plpgsql AS $$
DECLARE a booking.admissions%ROWTYPE; v_max int; v_new boolean;
BEGIN
  SELECT * INTO a FROM booking.admissions WHERE id = p_adm FOR UPDATE;
  IF a.status NOT IN ('ACTIVE','EDITABLE') OR a.expires_at <= clock_timestamp() THEN RETURN 'SESSION_EXPIRED'; END IF;
  SELECT max_attendee_checks_per_session INTO v_max FROM booking.events WHERE id = a.event_id;
  v_new := NOT EXISTS (SELECT 1 FROM booking.attendee_checks WHERE admission_id = p_adm AND attendee_nik_hash = p_nik);
  IF v_new THEN
    IF a.attendee_checks >= v_max THEN RETURN 'CHECK_LIMIT_REACHED'; END IF;
    INSERT INTO booking.attendee_checks(admission_id, attendee_nik_hash) VALUES (p_adm, p_nik);
    UPDATE booking.admissions SET attendee_checks = attendee_checks + 1 WHERE id = p_adm;
  END IF;
  IF EXISTS (SELECT 1 FROM booking.booking_items bi
              WHERE bi.event_id = a.event_id AND bi.attendee_nik_hash = p_nik AND bi.item_status IN ('HELD','PAID')
                AND bi.booking_id IS DISTINCT FROM (SELECT b.id FROM booking.bookings b WHERE b.admission_id = p_adm
                                                     AND b.status = 'PENDING_PAYMENT')) THEN
    RETURN 'ALREADY_REGISTERED';
  END IF;
  RETURN 'AVAILABLE';
END $$;

-- Kunci admission: pesanan tidak bisa diubah lagi; sisa unit yang tidak dipakai kembali ke stok bebas.
CREATE OR REPLACE FUNCTION booking_t.lock_admission(p_adm uuid, p_reason text) RETURNS void LANGUAGE plpgsql AS $$
DECLARE a booking.admissions%ROWTYPE; v_held int;
BEGIN
  SELECT * INTO a FROM booking.admissions WHERE id = p_adm FOR UPDATE;
  IF a.status <> 'EDITABLE' THEN RETURN; END IF;
  SELECT count(*) INTO v_held FROM booking.booking_items bi JOIN booking.bookings b ON b.id = bi.booking_id
   WHERE b.admission_id = p_adm AND bi.item_status = 'HELD';
  PERFORM 1 FROM booking.event_supply WHERE event_id = a.event_id FOR UPDATE;
  UPDATE booking.event_supply SET allocated_units = allocated_units - (a.units - v_held), version = version + 1
   WHERE event_id = a.event_id;
  UPDATE booking.admissions SET status = 'CONVERTED', locked_at = now(), lock_reason = p_reason,
         ended_at = now(), end_reason = 'CONVERTED'
   WHERE id = p_adm;
END $$;

-- Pilih kategori otomatis (dipakai harness untuk membuktikan jaminan: "kategori apa pun yang tersedia").
CREATE OR REPLACE FUNCTION booking_t.auto_pick(p_event uuid, p_n int, p_single boolean) RETURNS uuid[]
LANGUAGE plpgsql AS $$
DECLARE r record; v uuid[] := ARRAY[]::uuid[]; v_need int := p_n; v_take int; i int;
BEGIN
  FOR r IN SELECT category_id, capacity - held_quantity - sold_quantity AS free
             FROM booking.category_inventories WHERE event_id = p_event
            ORDER BY (capacity - held_quantity - sold_quantity) >= p_n DESC, category_id LOOP
    IF p_single AND r.free < p_n THEN CONTINUE; END IF;
    v_take := least(v_need, r.free);
    FOR i IN 1..v_take LOOP v := v || r.category_id; END LOOP;
    v_need := v_need - v_take;
    EXIT WHEN v_need = 0;
  END LOOP;
  IF v_need > 0 THEN RETURN NULL; END IF;
  RETURN v;
END $$;

-- Validasi pilihan (dipakai hold dan ubah pesanan). Mengembalikan NULL bila valid.
CREATE OR REPLACE FUNCTION booking_t.validate_pick(a booking.admissions, p_cats uuid[], p_niks bytea[]) RETURNS text
LANGUAGE plpgsql AS $$
DECLARE n int := array_length(p_niks, 1);
BEGIN
  IF n IS NULL OR n > a.units THEN RETURN 'QUANTITY_EXCEEDS_LIMIT'; END IF;
  IF (SELECT count(DISTINCT x) FROM unnest(p_niks) x) <> n THEN RETURN 'ATTENDEE_NIK_DUPLICATE_IN_ORDER'; END IF;
  IF p_cats IS NOT NULL THEN
    IF array_length(p_cats, 1) <> n THEN RETURN 'VALIDATION_ERROR'; END IF;
    IF NOT a.cfg_allow_mixed_categories AND (SELECT count(DISTINCT c) FROM unnest(p_cats) c) > 1 THEN
      RETURN 'MIXED_CATEGORIES_NOT_ALLOWED';
    END IF;
  END IF;
  RETURN NULL;
END $$;

-- Pasang item baru ke booking (dipanggil di dalam subtransaksi). Melempar exception bila gagal.
CREATE OR REPLACE FUNCTION booking_t.put_items(p_booking uuid, a booking.admissions, p_cats uuid[], p_niks bytea[])
RETURNS void LANGUAGE plpgsql AS $$
DECLARE r record; i int; n int := array_length(p_niks, 1); v_cats uuid[] := p_cats;
BEGIN
  IF v_cats IS NULL THEN
    v_cats := booking_t.auto_pick(a.event_id, n, NOT a.cfg_allow_mixed_categories);
    IF v_cats IS NULL THEN RAISE EXCEPTION 'GUARANTEE_VIOLATED' USING ERRCODE = 'P0002'; END IF;
  END IF;
  FOR r IN SELECT c.category_id, count(*) AS k, ci.capacity, ci.held_quantity, ci.sold_quantity
             FROM unnest(v_cats) AS c(category_id)
             JOIN booking.category_inventories ci ON ci.category_id = c.category_id AND ci.event_id = a.event_id
            GROUP BY c.category_id, ci.capacity, ci.held_quantity, ci.sold_quantity LOOP
    IF r.held_quantity + r.sold_quantity + r.k > r.capacity THEN
      RAISE EXCEPTION 'CATEGORY_UNAVAILABLE' USING ERRCODE = 'P0001';
    END IF;
  END LOOP;
  FOR i IN 1..n LOOP
    INSERT INTO booking.booking_items(booking_id, event_id, category_id, unit_price_minor, attendee_nik_hash,
                                      attendee_nik_masked, attendee_name, item_status)
    SELECT p_booking, a.event_id, v_cats[i], tc.price_minor, p_niks[i], '3174********0001', 'Pemegang', 'HELD'
      FROM booking.ticket_categories tc WHERE tc.id = v_cats[i];
  END LOOP;
  UPDATE booking.category_inventories ci SET held_quantity = ci.held_quantity + x.k
    FROM (SELECT c, count(*) k FROM unnest(v_cats) c GROUP BY c) x WHERE ci.category_id = x.c;
  UPDATE booking.bookings b SET item_quantity = n,
         amount_minor = (SELECT sum(unit_price_minor) FROM booking.booking_items
                          WHERE booking_id = p_booking AND item_status = 'HELD')
   WHERE b.id = p_booking;
END $$;

-- Hold (C.3) = "Lanjut ke Pembayaran". Diterima sampai expires_at + masa tenggang submit.
-- Bila ubah pesanan aktif, sisa unit TETAP dipegang (status EDITABLE) sampai pesanan terkunci.
CREATE OR REPLACE FUNCTION booking_t.hold(p_adm uuid, p_cats uuid[], p_niks bytea[]) RETURNS text
LANGUAGE plpgsql AS $$
DECLARE
  a booking.admissions%ROWTYPE; q booking.buyer_quotas%ROWTYPE;
  n int := array_length(p_niks, 1); v_booking uuid; v_err text;
BEGIN
  SELECT * INTO a FROM booking.admissions WHERE id = p_adm FOR UPDATE;
  IF a.status IN ('EDITABLE','CONVERTED') THEN RETURN 'ALREADY_HELD'; END IF;   -- retry tanpa Idempotency-Key
  IF a.status <> 'ACTIVE'
     OR clock_timestamp() > a.expires_at + make_interval(secs => a.cfg_submit_grace_seconds) THEN
    RETURN 'SESSION_EXPIRED';
  END IF;
  v_err := booking_t.validate_pick(a, p_cats, p_niks);
  IF v_err IS NOT NULL THEN RETURN v_err; END IF;
  PERFORM 1 FROM booking.event_supply WHERE event_id = a.event_id FOR UPDATE;
  SELECT * INTO q FROM booking.buyer_quotas WHERE event_id = a.event_id AND buyer_nik_hash = a.buyer_nik_hash FOR UPDATE;
  IF q.held_quantity + q.paid_quantity + n > q.max_quantity THEN RETURN 'QUANTITY_EXCEEDS_LIMIT'; END IF;
  PERFORM 1 FROM booking.category_inventories WHERE event_id = a.event_id ORDER BY category_id FOR UPDATE;
  BEGIN
    INSERT INTO booking.bookings(public_ref, event_id, admission_id, visitor_id, buyer_nik_hash, buyer_email, status,
                                 amount_minor, item_quantity, payment_expires_at)
    VALUES ('RB-' || substr(md5(random()::text), 1, 10), a.event_id, a.id, a.visitor_id, a.buyer_nik_hash,
            a.buyer_email, 'PENDING_PAYMENT', 0, n, now() + make_interval(secs => a.cfg_payment_ttl_seconds))
    RETURNING id INTO v_booking;
    PERFORM booking_t.put_items(v_booking, a, p_cats, p_niks);
  EXCEPTION
    WHEN unique_violation THEN RETURN 'ATTENDEE_NIK_ALREADY_REGISTERED';   -- sesi dan alokasi tetap utuh
    WHEN SQLSTATE 'P0001' THEN RETURN 'CATEGORY_UNAVAILABLE';
    WHEN SQLSTATE 'P0002' THEN RETURN 'GUARANTEE_VIOLATED';
  END;
  UPDATE booking.event_supply SET allocated_units = allocated_units - n, held_units = held_units + n,
         version = version + 1 WHERE event_id = a.event_id;
  UPDATE booking.buyer_quotas SET held_quantity = held_quantity + n
   WHERE event_id = a.event_id AND buyer_nik_hash = a.buyer_nik_hash;
  UPDATE booking.admissions SET status = 'EDITABLE' WHERE id = p_adm;
  IF NOT a.cfg_edit_enabled OR a.cfg_max_edits = 0 THEN
    PERFORM booking_t.lock_admission(p_adm, 'EDIT_DISABLED');
  ELSIF clock_timestamp() >= a.expires_at THEN
    PERFORM booking_t.lock_admission(p_adm, 'SELECTION_EXPIRED');            -- hold di masa tenggang
  END IF;
  RETURN 'OK';
END $$;

-- Ubah pesanan (v4.4): penggantian ATOMIK. Item lama dilepas dan item baru dipasang dalam satu subtransaksi;
-- bila item baru gagal (kategori habis, NIK bentrok), pesanan lama tetap utuh. TTL Pembayaran tidak di-reset.
CREATE OR REPLACE FUNCTION booking_t.replace_items(p_adm uuid, p_cats uuid[], p_niks bytea[]) RETURNS text
LANGUAGE plpgsql AS $$
DECLARE
  a booking.admissions%ROWTYPE; b booking.bookings%ROWTYPE; q booking.buyer_quotas%ROWTYPE;
  n int := array_length(p_niks, 1); v_old int; v_err text;
BEGIN
  SELECT * INTO a FROM booking.admissions WHERE id = p_adm FOR UPDATE;
  IF a.status = 'CONVERTED' THEN RETURN 'BOOKING_LOCKED'; END IF;
  IF a.status <> 'EDITABLE' THEN RETURN 'SESSION_EXPIRED'; END IF;
  IF clock_timestamp() > a.expires_at + make_interval(secs => a.cfg_submit_grace_seconds) THEN
    RETURN 'BOOKING_LOCKED';                                                 -- TTL detail habis; sweeper akan mengunci
  END IF;
  IF a.edit_count >= a.cfg_max_edits THEN RETURN 'EDIT_LIMIT_REACHED'; END IF;
  SELECT * INTO b FROM booking.bookings WHERE admission_id = p_adm FOR UPDATE;
  IF b.status <> 'PENDING_PAYMENT' OR b.payment_started_at IS NOT NULL THEN RETURN 'BOOKING_LOCKED'; END IF;
  v_err := booking_t.validate_pick(a, p_cats, p_niks);
  IF v_err IS NOT NULL THEN RETURN v_err; END IF;
  PERFORM 1 FROM booking.event_supply WHERE event_id = a.event_id FOR UPDATE;
  SELECT * INTO q FROM booking.buyer_quotas WHERE event_id = a.event_id AND buyer_nik_hash = a.buyer_nik_hash FOR UPDATE;
  PERFORM 1 FROM booking.category_inventories WHERE event_id = a.event_id ORDER BY category_id FOR UPDATE;
  v_old := b.item_quantity;
  IF q.held_quantity - v_old + q.paid_quantity + n > q.max_quantity THEN RETURN 'QUANTITY_EXCEEDS_LIMIT'; END IF;
  BEGIN
    UPDATE booking.category_inventories ci SET held_quantity = ci.held_quantity - x.k
      FROM (SELECT category_id c, count(*) k FROM booking.booking_items
             WHERE booking_id = b.id AND item_status = 'HELD' GROUP BY 1) x
     WHERE ci.category_id = x.c;
    UPDATE booking.booking_items SET item_status = 'REPLACED' WHERE booking_id = b.id AND item_status = 'HELD';
    PERFORM booking_t.put_items(b.id, a, p_cats, p_niks);
  EXCEPTION
    WHEN unique_violation THEN RETURN 'ATTENDEE_NIK_ALREADY_REGISTERED';   -- pesanan lama utuh
    WHEN SQLSTATE 'P0001' THEN RETURN 'CATEGORY_UNAVAILABLE';              -- pesanan lama utuh
    WHEN SQLSTATE 'P0002' THEN RETURN 'GUARANTEE_VIOLATED';
  END;
  UPDATE booking.event_supply SET allocated_units = allocated_units + v_old - n,
         held_units = held_units - v_old + n, version = version + 1 WHERE event_id = a.event_id;
  UPDATE booking.buyer_quotas SET held_quantity = held_quantity - v_old + n
   WHERE event_id = a.event_id AND buyer_nik_hash = a.buyer_nik_hash;
  UPDATE booking.bookings SET version = version + 1 WHERE id = b.id;
  UPDATE booking.admissions SET edit_count = edit_count + 1 WHERE id = p_adm;
  RETURN 'OK';
END $$;

-- Tombol "Bayar" (Payment memanggil Booking sebelum membuat transaksi di gateway). Idempoten.
-- Mengunci pesanan, melepas sisa unit, dan mengembalikan versi + nominal yang harus ditagih.
CREATE OR REPLACE FUNCTION booking_t.start_payment(p_booking uuid, OUT outcome text, OUT version int, OUT amount bigint)
LANGUAGE plpgsql AS $$
DECLARE b booking.bookings%ROWTYPE; v_adm uuid;
BEGIN
  SELECT admission_id INTO v_adm FROM booking.bookings WHERE id = p_booking;
  PERFORM 1 FROM booking.admissions WHERE id = v_adm FOR UPDATE;           -- urutan kunci sama dengan ubah pesanan
  SELECT * INTO b FROM booking.bookings WHERE id = p_booking FOR UPDATE;
  IF b.status <> 'PENDING_PAYMENT' THEN outcome := 'BOOKING_NOT_PAYABLE'; RETURN; END IF;
  IF clock_timestamp() >= b.payment_expires_at THEN outcome := 'PAYMENT_EXPIRED'; RETURN; END IF;
  IF b.payment_started_at IS NULL THEN
    UPDATE booking.bookings SET payment_started_at = now() WHERE id = p_booking;
  END IF;
  PERFORM booking_t.lock_admission(v_adm, 'PAYMENT_STARTED');
  outcome := 'OK'; version := b.version; amount := b.amount_minor;
END $$;

-- Sweeper TTL (dijalankan berkala): giliran tak diklaim, sesi tanpa hold, dan batas ubah pesanan.
CREATE OR REPLACE FUNCTION booking_t.sweep_admission(p_adm uuid) RETURNS text LANGUAGE plpgsql AS $$
DECLARE a booking.admissions%ROWTYPE;
BEGIN
  SELECT * INTO a FROM booking.admissions WHERE id = p_adm FOR UPDATE;
  IF a.status = 'RESERVED' AND clock_timestamp() > a.expires_at THEN
    PERFORM booking_t.end_admission(p_adm); RETURN 'UNCLAIMED';
  ELSIF a.status = 'ACTIVE' AND clock_timestamp() > a.expires_at + make_interval(secs => a.cfg_submit_grace_seconds) THEN
    PERFORM booking_t.end_admission(p_adm); RETURN 'SESSION_EXPIRED';
  ELSIF a.status = 'EDITABLE' AND clock_timestamp() > a.expires_at + make_interval(secs => a.cfg_submit_grace_seconds) THEN
    PERFORM booking_t.lock_admission(p_adm, 'SELECTION_EXPIRED'); RETURN 'LOCKED';
  END IF;
  RETURN 'NOOP';
END $$;

CREATE OR REPLACE FUNCTION booking_t.finish_booking(p_booking uuid, p_paid boolean) RETURNS void LANGUAGE plpgsql AS $$
DECLARE b booking.bookings%ROWTYPE;
BEGIN
  PERFORM 1 FROM booking.admissions WHERE id = (SELECT admission_id FROM booking.bookings WHERE id = p_booking) FOR UPDATE;
  SELECT * INTO b FROM booking.bookings WHERE id = p_booking FOR UPDATE;
  IF b.status <> 'PENDING_PAYMENT' THEN RETURN; END IF;
  IF p_paid AND b.payment_started_at IS NULL THEN
    RAISE EXCEPTION 'tidak mungkin dibayar sebelum pesanan terkunci (booking %)', p_booking;
  END IF;
  PERFORM booking_t.lock_admission(b.admission_id, 'BOOKING_ENDED');       -- no-op bila sudah terkunci
  PERFORM 1 FROM booking.event_supply WHERE event_id = b.event_id FOR UPDATE;
  PERFORM 1 FROM booking.buyer_quotas WHERE event_id = b.event_id AND buyer_nik_hash = b.buyer_nik_hash FOR UPDATE;
  PERFORM 1 FROM booking.category_inventories WHERE event_id = b.event_id ORDER BY category_id FOR UPDATE;
  IF p_paid THEN
    UPDATE booking.category_inventories ci SET held_quantity = held_quantity - x.k, sold_quantity = sold_quantity + x.k
      FROM (SELECT category_id c, count(*) k FROM booking.booking_items
             WHERE booking_id = p_booking AND item_status = 'HELD' GROUP BY 1) x
     WHERE ci.category_id = x.c;
    UPDATE booking.event_supply SET held_units = held_units - b.item_quantity, sold_units = sold_units + b.item_quantity
     WHERE event_id = b.event_id;
    UPDATE booking.buyer_quotas SET held_quantity = held_quantity - b.item_quantity,
           paid_quantity = paid_quantity + b.item_quantity
     WHERE event_id = b.event_id AND buyer_nik_hash = b.buyer_nik_hash;
    UPDATE booking.booking_items SET item_status = 'PAID' WHERE booking_id = p_booking AND item_status = 'HELD';
    UPDATE booking.bookings SET status = 'PAID', paid_at = now(), settlement_time = now(), ended_at = now()
     WHERE id = p_booking;
  ELSE
    UPDATE booking.category_inventories ci SET held_quantity = held_quantity - x.k
      FROM (SELECT category_id c, count(*) k FROM booking.booking_items
             WHERE booking_id = p_booking AND item_status = 'HELD' GROUP BY 1) x
     WHERE ci.category_id = x.c;
    UPDATE booking.event_supply SET held_units = held_units - b.item_quantity WHERE event_id = b.event_id;
    UPDATE booking.buyer_quotas SET held_quantity = held_quantity - b.item_quantity
     WHERE event_id = b.event_id AND buyer_nik_hash = b.buyer_nik_hash;
    UPDATE booking.booking_items SET item_status = 'RELEASED' WHERE booking_id = p_booking AND item_status = 'HELD';
    UPDATE booking.bookings SET status = 'EXPIRED', ended_at = now() WHERE id = p_booking;
  END IF;
END $$;

-- Akhir giliran tanpa pesanan (tidak diklaim, sesi habis tanpa hold, keluar).
CREATE OR REPLACE FUNCTION booking_t.end_admission(p_adm uuid) RETURNS void LANGUAGE plpgsql AS $$
DECLARE a booking.admissions%ROWTYPE;
BEGIN
  SELECT * INTO a FROM booking.admissions WHERE id = p_adm FOR UPDATE;
  IF a.status NOT IN ('RESERVED','ACTIVE') THEN RETURN; END IF;           -- EDITABLE punya pesanan: tidak berakhir di sini
  PERFORM 1 FROM booking.event_supply WHERE event_id = a.event_id FOR UPDATE;
  UPDATE booking.admissions SET status = 'EXPIRED', ended_at = now(),
         end_reason = CASE WHEN a.status = 'RESERVED' THEN 'UNCLAIMED' ELSE 'LEFT_WITHOUT_BUYING' END
   WHERE id = p_adm;
  UPDATE booking.event_supply SET allocated_units = allocated_units - a.units WHERE event_id = a.event_id;
END $$;

-- Invarian yang wajib selalu benar (dipakai setiap langkah simulasi).
CREATE OR REPLACE FUNCTION booking_t.assert_invariants(p_event uuid) RETURNS void LANGUAGE plpgsql AS $$
DECLARE s booking.event_supply%ROWTYPE; v int; w int; bad int;
BEGIN
  SELECT * INTO s FROM booking.event_supply WHERE event_id = p_event;
  SELECT sum(capacity) INTO v FROM booking.category_inventories WHERE event_id = p_event;
  IF v <> s.total_capacity THEN RAISE EXCEPTION 'INV: sum categories % <> total %', v, s.total_capacity; END IF;
  -- alokasi = unit giliran yang belum punya pesanan + sisa unit pesanan yang masih bisa diubah
  SELECT COALESCE(sum(CASE WHEN a.status IN ('RESERVED','ACTIVE') THEN a.units
                           ELSE a.units - (SELECT count(*) FROM booking.booking_items bi JOIN booking.bookings b
                                             ON b.id = bi.booking_id
                                            WHERE b.admission_id = a.id AND bi.item_status = 'HELD') END), 0)
    INTO v FROM booking.admissions a WHERE a.event_id = p_event AND a.status IN ('RESERVED','ACTIVE','EDITABLE');
  IF v <> s.allocated_units THEN RAISE EXCEPTION 'INV: allocated % <> %', s.allocated_units, v; END IF;
  SELECT count(*) FILTER (WHERE item_status='HELD'), count(*) FILTER (WHERE item_status='PAID') INTO v, w
    FROM booking.booking_items WHERE event_id = p_event;
  IF v <> s.held_units OR w <> s.sold_units THEN RAISE EXCEPTION 'INV: held/sold mismatch'; END IF;
  SELECT count(*) INTO bad FROM booking.category_inventories ci
   WHERE ci.event_id = p_event AND (ci.held_quantity <> (SELECT count(*) FROM booking.booking_items i
            WHERE i.category_id = ci.category_id AND i.item_status='HELD')
         OR ci.sold_quantity <> (SELECT count(*) FROM booking.booking_items i
            WHERE i.category_id = ci.category_id AND i.item_status='PAID'));
  IF bad > 0 THEN RAISE EXCEPTION 'INV: category counters mismatch'; END IF;
  SELECT count(*) INTO bad FROM booking.buyer_quotas bq
   WHERE bq.event_id = p_event AND (bq.held_quantity + bq.paid_quantity) <> (
     SELECT count(*) FROM booking.booking_items i JOIN booking.bookings b ON b.id = i.booking_id
      WHERE b.event_id = p_event AND b.buyer_nik_hash = bq.buyer_nik_hash AND i.item_status IN ('HELD','PAID'));
  IF bad > 0 THEN RAISE EXCEPTION 'INV: buyer quota mismatch'; END IF;
  -- jumlah item aktif per booking = item_quantity; nominal = jumlah harga item aktif
  SELECT count(*) INTO bad FROM booking.bookings b WHERE b.event_id = p_event AND b.status IN ('PENDING_PAYMENT','PAID')
     AND EXISTS (SELECT 1 FROM booking.booking_items i WHERE i.booking_id = b.id AND i.item_status IN ('HELD','PAID')
                 HAVING count(*) <> b.item_quantity OR sum(i.unit_price_minor) <> b.amount_minor);
  IF bad > 0 THEN RAISE EXCEPTION 'INV: booking item_quantity/amount mismatch'; END IF;
  -- pesanan yang bisa diubah belum pernah mulai bayar; pesanan yang mulai bayar selalu terkunci
  SELECT count(*) INTO bad FROM booking.admissions a JOIN booking.bookings b ON b.admission_id = a.id
   WHERE a.event_id = p_event AND ((a.status = 'EDITABLE' AND (b.payment_started_at IS NOT NULL OR b.status <> 'PENDING_PAYMENT'))
                                OR (b.payment_started_at IS NOT NULL AND a.status <> 'CONVERTED'));
  IF bad > 0 THEN RAISE EXCEPTION 'INV: edit/lock state mismatch'; END IF;
  -- Jaminan: stok fisik bebas di semua kategori >= unit yang sudah dialokasikan
  SELECT sum(capacity - held_quantity - sold_quantity) INTO v FROM booking.category_inventories WHERE event_id = p_event;
  IF v < s.allocated_units THEN RAISE EXCEPTION 'INV: physical free % < allocated %', v, s.allocated_units; END IF;
END $$;
```

Cara menjalankan: terapkan DDL Lampiran B [v4.6 → SDD §4.4] ke database kosong, jalankan file ini, lalu skrip uji T1–T22, simulasi, dan uji paralel yang disimpan di `tests/design/` repository. Fungsi `replace_items`, `start_payment`, dan `sweep_admission` adalah acuan untuk C.8–C.10.

## Annex C — Assessment Evidence and Technical Defense

### Technical Defense

*Sumber: PRD v4.6 §24.2*

| Pertanyaan assessor | Jawaban singkat |
|---|---|
| Bagaimana menjamin yang masuk pasti dapat tiket? | Giliran hanya diberikan bila Booking berhasil mereservasi N unit stok untuk customer itu; `allocated + held + sold ≤ total` dan `total = Σ kapasitas kategori` dijaga constraint DB, sehingga stok fisik bebas selalu ≥ unit yang dijanjikan. Dibuktikan simulasi acak dan uji paralel |
| Kalau kategori incaran habis saat customer sudah di dalam? | Kategori tidak dijanjikan dan ditampilkan live; jumlah tiket tetap dijamin, dan campuran kategori lain pasti cukup. Reservasi tidak hilang saat kategori gagal |
| Bagaimana tidak PHP di antrean? | Indikator peluang dari stok riil, notifikasi "tidak cukup" untuk posisi yang mustahil, penutupan waiting room otomatis saat habis |
| Bagaimana 1 juta pengantre tidak menjatuhkan server? | Status antrean satu dokumen di CDN; origin hanya melayani join dan klaim; beban origin tidak bergantung jumlah pengantre |
| Kenapa 5 service dan bukan lebih? | Mengikuti aktor requirement; semua yang menyentuh stok ada di satu service sehingga stok tidak memerlukan transaksi terdistribusi; langkah lintas service memakai saga koreografi dengan kompensasi (ADR-018); User Service ditambahkan untuk akun opsional dengan login OTP (ADR-020) |
| Bagaimana kalau Payment Service down saat TTL habis? | Booking tidak melepas stok; status VERIFYING sampai masa tenggang; customer tidak dibatalkan sepihak |
| Bagaimana kalau webhook terlambat? | Tepat waktu dinilai dari `settlement_time`; resolve aktif ke gateway sebelum expired |
| Bagaimana mencegah calo? | Satu NIK pemegang satu tiket per event, kuota 3 per NIK pembeli per event, satu antrean aktif per NIK/perangkat/email, cek NIK langsung yang dibatasi, validasi struktur NIK, WAF challenge (§14.5 [v4.6 → HLD §4.6]) |
| Bagaimana FIFO dijamin di banyak instance? | Sequence dari satu Valkey `INCR` per event; promotor tunggal per event dengan lease |
| Bagaimana biaya dikendalikan? | Biaya per penjualan dominan di request CDN; polling adaptif; scale-out terjadwal |
| Requirement minta real time, kenapa tidak SSE/WebSocket? | Yang diminta adalah tidak PHP dan adil. Urutan ditentukan nomor antrean server dan keabsahan aksi diputuskan server, jadi telat beberapa detik tidak merugikan siapa pun. Batas keterlambatan ditetapkan dan diukur (§5.25 [v4.6 → SRS §3.2.25]). SSE/WebSocket di waiting room berarti 1 juta koneksi terbuka di origin tanpa menambah keadilan. SSE dipakai di halaman detail yang jumlah penggunanya terbatas |
| Bagaimana bila HP customer di background saat giliran tiba? | Peringatan sebelum giliran, push notification, dan jendela klaim 3 menit. Tidak ada prioritas untuk giliran hangus agar urutan tetap adil |
| Boleh mengubah pesanan setelah lanjut bayar? | Boleh sampai menekan "Bayar" selama TTL Booking; sisa unit tetap dipegang sehingga jaminan N tetap berlaku; penggantian atomik; setelah "Bayar" terkunci agar nominal di gateway pasti sama |
| Bagaimana kalau koneksi putus saat lanjut bayar? | Satu `Idempotency-Key` per tombol, klien memulihkan status dari server sebelum mengirim ulang; tidak mungkin hold ganda; masa tenggang 5 detik untuk detik terakhir |
| Kenapa Valkey, dan kenapa stok tidak disimpan di Valkey? | Valkey tepat untuk antrean (INCR, sorted set, Lua atomik), open source BSD, dan lebih murah di ElastiCache. Stok tetap di PostgreSQL karena replikasi in-memory async dapat kehilangan tulisan saat failover; bagi customer itu berarti tiket yang dijanjikan hilang. Tulisan stok hanya < 250/detik karena dibatasi slot aktif, jadi PostgreSQL tidak menjadi bottleneck |
| Bagaimana kode dijaga tetap rapi dengan timeline 4 minggu? | Hexagonal + SOLID gaya Go (§7.4 [v4.6 → SDD §4.5]), unit of work untuk transaksi stok, depguard untuk batas service, contract test untuk setiap port |
| Bagaimana sikap sistem terhadap teorema CAP? | Per komponen, menurut akibat bila data salah (§9.7 [v4.6 → HLD §4.3]): stok dan uang **CP** di PostgreSQL (lebih baik menolak sementara daripada menjual unit yang sama dua kali); penerbitan nomor antrean fail closed; cache, Status Document, dan notifikasi **AP** karena basi beberapa detik tidak merugikan siapa pun. Tidak ada transaksi terdistribusi karena semua yang menyentuh stok ada di satu service |
| Kenapa outbox hanya di Booking dan Payment? | Hanya event dari dua service itu yang membawa akibat uang atau tiket; tanpa outbox, crash di antara commit dan publish bisa membuat customer sudah bayar tanpa tiket. Event Queue hanya push best effort, jadi publish langsung cukup |
| Tanpa tabel inbox, bagaimana pesan ganda ditangani? | Idempotensi dari data bisnis: guard state machine, Lua idempoten, dan unique key (§9.8 [v4.6 → SDD §4.5.2]). Setiap consumer diuji dengan pesan ganda (TC-MSG-03). Lebih sedikit tabel, jaminan sama |
| Bagaimana konfigurasi diubah dengan aman saat penjualan? | Nilai di-snapshot per sesi, aturan jaminan dikunci saat penjualan dibuka, validasi silang, dan audit setiap perubahan |

### Claims to Avoid

*Sumber: PRD v4.6 §24.3*

Tidak mengklaim exactly-once email atau push (keduanya at-least-once), HA penuh di PoC, Sandbox sebagai SLA production, compliance PCI-DSS penuh, kapasitas Tier L sebelum ekstrapolasi dari bukti PoC, verifikasi identitas dari validasi struktur NIK, calo hilang sepenuhnya, kategori favorit dijamin, push notification pasti sampai, atau latensi sub-detik di waiting room.

Alur tindak lanjut: temuan → issue (`security`, severity, owner) → PR perbaikan dengan test regresi → re-scan → issue ditutup dengan tautan bukti. Temuan HIGH/CRITICAL memblokir rilis kecuali ada risk acceptance tertulis (SRS-Q-SEC-08).
