# Keputusan dan batas pengerjaan SCRUM-53 sampai SCRUM-56

Tanggal: 2026-11-02. Berdasarkan diskusi dengan pemilik (arnu12rahman) dan hasil E2E manual di dev.

## SCRUM-53: access token dicabut saat logout
- Access token memuat `sid` (id sesi User). Logout menulis `sid` ke Valkey (`rbt:revoked:sid:<sid>`) selama `TOKEN_ACCESS_TTL + 30 detik`; entri hilang sendiri, token yang sudah kedaluwarsa tidak disimpan.
- Pengecekan ada di verifier: User (`/me`), Booking (admin dan pembeli), Queue (akun login). **Fail closed**: bila Valkey tidak bisa dibaca, token ditolak. Token lama tanpa `sid` tetap berlaku sampai `exp`.
- TTL access token tidak diubah (15 menit): pemilik tidak ingin FE sering refresh.
- Syarat operasi: semua service memakai Valkey dan `VALKEY_PREFIX_ENV` yang sama.
- **Batas yang diketahui:** access token yang terbit sebelum refresh terakhir memakai `sid` sesi sebelumnya dan tidak ikut dicabut (umurnya paling lama TOKEN_ACCESS_TTL). Penyelesaian penuh butuh id keluarga sesi yang tetap sepanjang rotasi. Payment dan Notification tidak memeriksa token pembeli, jadi tidak terpengaruh.

## SCRUM-55: status publikasi
- `published_at` kosong = draf, terisi = terbit. Event lama ditandai terbit lewat migrasi `0007` agar katalog tidak kosong. Status ketersediaan tetap dihitung dari jendela penjualan.
- Katalog dan detail publik hanya event terbit (draf 404). Supply (dipakai Queue) dan alokasi menolak draf. Admin: GET detail termasuk draf, POST publish, POST unpublish (hanya sebelum penjualan dibuka).
- Event baru dari admin berstatus draf, jadi E2E dan panduan menambah satu langkah (create lalu publish).

## SCRUM-56: CANCELLED
- Status tersimpan (migrasi `0008`) yang mengalahkan status turunan. Daftar katalog bawaan menyembunyikannya, detail tetap terbuka dengan status `CANCELLED` (bukan 404) supaya pembeli yang sudah membeli tidak melihat error.
- Penjualan berhenti: alokasi (tidak ada admission baru), hold (409 `EVENT_CANCELLED`), supply (`soldOut`).
- **Belum dikerjakan:** pembatalan paksa booking `PENDING_PAYMENT` (habis sendiri sesuai batas bayar), pemblokiran attempt pembayaran baru di Payment, penolakan join di Queue untuk event yang sudah punya pengaturan antrean, dan email pembatalan. Refund otomatis ada di SCRUM-57 (backlog).

## Temuan E2E yang diperbaiki
- Token service Queue ke Booking dibuat sekali (24 jam) lalu kedaluwarsa; kini diperbarui otomatis (5 menit, cache).
- `POST /bookings` kedua di sesi yang sama menjawab 500; kini 403 `ADMISSION_TOKEN_INVALID`.
- Join menerima email tanpa format valid; kini 400.
- Notification mencatat log saat e-tiket terkirim (tanpa email penerima).

## Bukan bug (setelah dicek)
- Cancel manual menyimpan booking sebagai `EXPIRED` dengan `reason=CANCELLED` pada event `booking.expired` (sesuai desain notification).
- `queue-entries/me` tanpa token menjawab 404: sesuai kontrak (hanya 200, 404, 429 yang didokumentasikan).
