# E2E ke ADR-030 dan penyelarasan 08a-frontend-integration (2026-11-09)

## Diskusi
Pemilik meminta suite e2e disesuaikan dengan ADR-030 (join anonim, `buyer` diisi saat hold) dan `08a-frontend-integration.md` diselaraskan dengan kontrak OpenAPI. Perubahan hanya tes dan dokumen; tidak ada kode produksi (`services/*/internal`, `pkg/`) yang diubah dan `services/booking` tidak disentuh.

## Akar masalah e2e
Sejak ADR-030 `POST /api/v1/bookings` mewajibkan blok `buyer` `{nik,email,emailConfirmation,consent:true}` (`hold.go` memvalidasi `req.Buyer.NIK`); tes lama hanya mengirim `sessionId` + `items` sehingga hold ditolak `422 NIK_INVALID` (uji sell-out melihat 0 hold, bukan 2). Join anonim: body tidak dibaca.

## Perubahan tes
- `journey_test.go`, `failures_test.go`: setiap hold memakai `buyer` (NIK unik valid per pembeli), join tanpa body (`X-Client-Type: mobile` agar `visitorToken` ada di body), `adminEmail` memakai `E2E_ADMIN_DOMAIN` (bawaan `admin.e2e.test`).
- `helpers/admit.go`: join tanpa body, claim memakai `?eventId=` (wajib di kontrak), gagal bila tidak ADMITTED dalam 15 s (sebelumnya jatuh diam-diam ke claim), poll 200 ms (promotor ~100 ms), `HoldTickets` menerima `AdmitResult` (membawa NIK/email pembeli), `HoldTicketsAs` untuk NIK pembeli eksplisit.
- `steps/*`: pemanggil `HoldTickets` mengikuti signature baru; `queue_steps` join anonim.
- `tests/features/guest.feature` + `steps/guest_steps.go`: skenario lama (join dengan NIK invalid -> 422, join ulang -> 409) sudah salah sejak ADR-030; diganti: join anonim, body lama diabaikan (201), join ulang oleh visitor sama -> 200 entri sama. Step status memakai kalimat sendiri ("the join response status is") karena "the response status is N" bentrok dengan step catalog (catalog terdaftar lebih dulu; pre-existing: "no response recorded").
- `helpers/db.go` `ForceExpireBooking`: juga memundurkan `created_at` (skema: `payment_expires_at > created_at`); sebelumnya `bookings_check` melanggar.
- `tests/e2e/go.mod/go.sum`: `go mod tidy` (godog, pgx, amqp091 dipakai `main_test.go`/`helpers`/`steps` tetapi tidak ada di go.mod modul ini, sehingga seluruh paket tidak terkompilasi).

## Perintah
```
cd tests/e2e
GOWORK=off go vet -tags e2e ./...
export GOWORK=off TEST_POSTGRES_DSN='postgres://root:root@localhost:5432/berebut?sslmode=disable' E2E_ADMIN_DOMAIN=admin.sim.test
go test -tags e2e -count=1 -skip 'TestE2E$' -v .                       # tes Go biasa
MIDTRANS_SERVER_KEY=dummy go test -tags e2e -count=1 -run 'TestJourney|TestPayment|TestHold' -v .   # memaksa tes Payment jalan sampai langkah Payment
go test -tags e2e -count=1 -run 'TestE2E$' -v .                        # BDD godog (tests/features)
```
Service lokal milik pemilik (queue :8081, booking :8082, notification :8084, user :8085); Payment :8083 tidak berjalan. Tidak ada kontainer yang dibuat/dihentikan, klaster Valkey tidak disentuh; data hanya lewat API (dan fixture SQL yang sudah ada di helper BDD).

## Dokumen 08a: ketidakcocokan yang diperbaiki
Lihat commit. Ringkas: join (field respons `entryId`/`state`/`rank`, tanpa `id`/`config`; kode 409 lama NIK/VISITOR/EMAIL/BUYER_QUOTA diganti yang di kontrak; 200 vs 201; `X-Device-Id`, `Idempotency-Key`), status document (`saleState`, `poll`, `nextPollAfterMs`, tanpa `config.pollingIntervalMs`/`saleStatus`), me/heartbeat/leave ditambahkan, claim (tanpa bearer `queueToken`, `?eventId=` wajib, kode `NOT_ADMITTED`/`TURN_MISSED`/`EVENT_SOLD_OUT`/`VISITOR_TOKEN_INVALID`), sesi (`sessionId`, `phase`, `reservedUnits`, `priceMinor`, tanpa `config`; `current`, `cancel`), SSE (event `timer`, bukan `session`; payload nyata), attendee-checks (`{nik}` -> `{result, checksRemaining}`), hold (blok `buyer`, `attendee{nik,fullName}`, `Idempotency-Key` wajib 16..64, respons `Booking`, tabel error), amplop error (`meta.message` "KODE: pesan", bukan `error{}`), tabel token (queueToken tak dipakai, refreshToken di body bukan cookie), CDN (parameter `events` yang benar, tanpa `page`/`size`; facets), push (`pushToken`, port 8084, `X-Visitor-Token`), versi/tanggal.

## Kontrak vs kode (tidak dipilih; dicatat di akhir 08a)
1. `X-Client-Type: mobile` menentukan `visitorToken` di body join; tidak ada di `queue.yaml`.
2. `X-Device-Id` terdaftar di kontrak hanya pada join/heartbeat; kode juga memeriksanya di `me` (claim/leave tidak diverifikasi).
3. `queueToken` dikembalikan tetapi tidak dipakai endpoint mana pun.
4. `ENTRY_MOVED` terdaftar di kode, tidak dihasilkan dan tidak ada di kontrak.

## Tidak diverifikasi
Alur Payment/Midtrans (webhook, e-tiket, expiry-REVIEW), `TestExpiredPayment_*` (E2E_SLOW), contoh JSON di 08a diperiksa terhadap skema kontrak dan kode, bukan dijalankan satu per satu terhadap server.
