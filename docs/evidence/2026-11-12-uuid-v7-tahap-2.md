# UUIDv7 tahap 2 (ADR-032): bukti uji — 2026-11-12

Perubahan: migrasi default `id` ke `uuid_generate_v7()` (booking 0012, notification 0002, user 0003, payment 0006), `queue/valueobject.NewUUID` dan `user/security.SessionID` menghasilkan v7. Keputusan teknis: domain queue hanya boleh stdlib (depguard), jadi generator ditulis ulang, bukan memanggil `pkg/rabbitmq.NewID` seperti tertulis di tindak lanjut ADR-032 sebelumnya.

## Hasil
- Unit test: queue (`TestNewUUID_IsV7`: format v7, 1000 ID unik, 48 bit pertama = waktu Unix ms), user (`TestSecrets_SessionID` kini mewajibkan versi 7), `embed_test` empat service memeriksa migrasi baru. Semua `go test ./...` di queue dan user lulus.
- SQL diuji di PostgreSQL 16 lokal dalam transaksi ROLLBACK: booking 7 kolom, notification 1, users 2, payment 4 (termasuk outbox 0005) memakai `uuid_generate_v7()`; ID hasilnya versi 7.
- Stack lokal dibangun ulang: runner migrasi menerapkan booking 12, payment 6, users 3, notification 2 (queue tetap 5).
- `tests/k6/scenarios/e2e.js` (1 VU, 1 iterasi) lulus; baris baru di `bookings`, `payment_attempts`, `sessions`, `deliveries` semuanya versi 7 (1/1, 1/1, 3/3, 1/1). `admissions`, `booking.outbox_events`, `payment.outbox_events`: baris baru v7, baris lama tetap v4 (9960, 14827, 54), tidak dimigrasi.

## Belum diuji
